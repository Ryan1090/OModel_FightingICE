# Consolidation and verification scope

This is a new approved software release, not a byte-identical copy of one old
launcher. Original research sources, reports, completed catalogue and global V16
remain unchanged.

The consolidation:

1. Captures the actual final natural/generation stock models, eligibility masks,
   scales, loadings, bounds and numeric-direction audit as release-hashed data.
   This replaces the historical import/reconstruction chain, not its values.
2. Extracts the actual constructor, graph, metric, core-score, support-trimming,
   far-qualification and inverse-readout functions. The default constructor and
   its full audit rows are compared exactly with the original implementation.
3. Materialises the final V27/V26 screen functions once, instead of replaying
   successive runtime source transformations. The screen traversal, selection,
   batch mechanics and V41 witness are checked for identical function bodies.
4. Applies the existing owned-listener readiness correction to the execution
   class, and installs the existing display-only status optimisation, compiler
   cache and minute counters in one runtime module. Scientific durability and
   observation/assessment code remain intact.
5. Replaces run-specific paths, descriptors and hard-coded counts with one
   validated configuration, package-owned assets and per-run commitments. Pool
   amounts flow through scheduling, references, accounting and final checks.
   Role ranges flow through both sampling and readout. Default values retain
   the validated design; custom configurations remain new experiments.
6. Provides one foreground/background entry point and explicit Status/Pause/
   Resume/Check commands. No old catalogue is imported into a new run and a
   completed archive is not reopened.

The archived V33/V41 live regressions remain historical evidence. Packaging was
verified through software equivalence and integration controls; no new gameplay
regression or new catalogue is claimed. The Windows worker-spawn control only
boots a worker and sends its exit sentinel; it starts no engine. The admission
integration control uses explicit software fixtures to test all five screens and
completed-commit reuse.

The first software run caught an overly strict writer guard comparing a
per-candidate configuration binding with the base run binding. The guard now
checks the run namespace, release binding, enabled capability and resolved output
root, while the existing candidate commitment binds the candidate/reference
configuration. A later Windows multiprocessing-pipe check required execution
outside the filesystem sandbox. These were engineering controls, with no
scientific evidence or catalogue verdict changed.

The model snapshot is a trusted Python/numpy data artifact. Its release digest is
verified before it is deserialised; do not substitute untrusted pickle files.

The historical completed run retained 626 old tables and added four under the
corrected witness. A fresh run of this release applies the corrected witness
consistently from its first candidate. This does not retroactively replace any
of those 626 tables or install the separate 49 replay proposals.
